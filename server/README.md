# Server

Authoritative game server: Colyseus rooms, Showdown battle sim, Postgres.

## Commands

```
npm install
cp .env.example .env     # optional; defaults match docker-compose.yml
npm run dev              # start with auto-restart on file changes (ws://localhost:2567)
npm run bot -- Ash       # headless test player that walks to Route 2 (server must be running)
npm run battle:demo      # one Gen 6 battle in the terminal: Lucario Mega Evolves vs a wild Fletchling
npm run test:auth        # end-to-end account/login checks (server must be running)
npm run test:battle      # starter, healing, walk to Route 2 and catch a wild Pokémon (server must be running)
npm run db:migrate       # apply db/migrations (needs Postgres: docker compose up -d)
npm run typecheck
```

## Layout

```
src/index.ts           registers one room per map and starts the server
src/auth/              register/login routes, scrypt passwords, sessions, rate limits
src/rooms/MapRoom.ts   login check, movement, warps, grass encounters — all validated server-side
src/world/online.ts    one connection per trainer
src/rooms/state.ts     state synced to clients (players in the room)
src/world/maps.ts      loads data/maps, tile/warp/encounter helpers
src/world/transfers.ts warp tickets so clients can't choose where they arrive
src/battle/showdown.ts Showdown sim wrapper
src/battle/pokemon.ts  generating Pokémon, stats, EXP curves, level-up moves, evolutions
src/battle/wild.ts     a wild battle: Showdown + wild AI, Poké Balls, running, EXP, messages
src/battle/party.ts    party, PC and bag in Postgres; starters
data/species.json      catch rates, EXP yields, growth rates (what Showdown's dex lacks)
src/db/pool.ts         Postgres pool + transaction helper
data/maps/*.json       map data: Vaniville has the real walkable tiles (importer/tools/make_map.py);
                       spawns, warps and the other maps are hand-written placeholders
db/migrations/*.sql    database schema
```

## Accounts

HTTP on the same port (`http://localhost:2567`), JSON bodies:

| Request | Body | Response |
|---|---|---|
| `POST /auth/register` | `{ username, password, trainerName }` | `201 { token, trainer }` |
| `POST /auth/login` | `{ username, password }` | `200 { token, trainer }` |
| `POST /auth/logout` | header `Authorization: Bearer <token>` | `204` |
| `GET /auth/me` | header `Authorization: Bearer <token>` | `200 { trainer }` |
| `GET /trainer/party` | Bearer | `200 { party: [{ species, name, level, hp, maxHp, status, moves }], items: { pokeball: n } }` |
| `POST /trainer/starter` | `{ species }` (chespin/fennekin/froakie), Bearer | `201 { party, items }`; 409 if the trainer already has a Pokémon. Comes with 10 Poké Balls |

`trainer` is `{ name, mapId, x, y, facing, appearance, introDone }`. `appearance` is `null` until character
creation, which saves it with `PUT /trainer/appearance { look }` (Bearer token):

```
{ "gender": "f2", "hairColor": 0, "skinTone": 1,
  "parts": { "face": {"part":"f2_face01"}, "tops": {"part":"f2_tops_jersey","color":"d01b02"}, ... } }
```

`story` lists the story events seen (`intro`, `neighbors`, ...). The client marks the cutscenes it
plays itself with `POST /trainer/story { event }` (only `neighbors` so far; Bearer, after the intro).
`introDone` is false until the client finishes the intro (Sycamore's welcome, waking up at home)
and calls `POST /trainer/intro` (Bearer, needs a look first) → `200 { trainer }`. Story flags live
in the `trainers.flags` JSONB column; only the server sets them.

Looks are checked against `data/appearance.json` (part ids and color codes only, generated by
`importer/tools/make_catalog.py`): face, hair, shoes and bag are required, plus top + bottoms or a
one-piece; hat, accessory (needs a hat) and girls' socks are optional. Other players get it as the
`look` field (JSON) of their room state. Errors are `{ error }` with 400 (invalid input),
401 (wrong login), 409 (username or trainer name taken) or 429 (rate limited).

- Usernames: 3–16 letters, digits or `_`, case-insensitive. Passwords: 8–128 characters, hashed with scrypt.
- Tokens last 30 days. Only their SHA-256 is stored.
- Rate limits: 10 logins per 15 min (per IP and per username), 30 register attempts per 15 min and
  5 new accounts per hour (per IP). Running the tests repeatedly hits these; start the server with
  `AUTH_RATE_LIMITS=off` for local testing only.
- A trainer can be online once. Logging in again closes the older connection with code `4001`.
- Rooms check the token in the **static** `MapRoom.onAuth` (the seat-reservation stage): the Godot
  SDK sends it only there. The map/ticket check is in `onJoin`. Colyseus's own `@colyseus/auth`
  is off (`auth: false`), since it would discard tokens that aren't its JWTs.

## Client protocol

Log in first, set the token on the SDK (`client.auth.token = token`), then join the map in
`trainer.mapId` with `{ ticket? }`. Joining any other map without a warp ticket is refused (403).

| Direction | Message | Payload |
|---|---|---|
| client → server | `move` | `"up" \| "down" \| "left" \| "right"` |
| client → server | `battle` | `{ type: "move", index }`, `{ type: "switch", slot }`, `{ type: "ball", item }` or `{ type: "run" }` |
| server → client | `warp` | `{ to, ticket, blackout? }` — leave this room, join `to` with `{ ticket }` |
| server → client | `battleStart` / `battleUpdate` | `{ events, view, request, result? }` (see `src/battle/wild.ts`) |
| server → client | `healed` | — walked into your front door; Mom healed the party |

Wild battles: stepping on tall grass (`G`) may start one if the party has a Pokémon that can fight.
The room blocks walking until it ends. `events` are messages and HP changes to play back in order;
`request` is what to choose next (a move, or a forced switch after a faint), null once `result` is
set (`win`, `caught`, `ran` or `lost`). Losing heals the party and warps you to your front door.
EXP, EVs, level-up moves and level-up evolutions are applied when the battle ends; catching gives
EXP too (Gen 6).

Synced state: `mapId`, `originX`/`originY` (where tile (0, 0) sits on the X/Y overworld, in global
tiles; -1 for placeholder maps), `players` (map of sessionId → `{ name, x, y, facing, look }`).

Vaniville, Route 1, Aquacorde and Route 2 are slices of one overworld (map01). Each owns a band of
rows; the row just past each edge is a warp onto the same tile of the neighbouring map, so clients
that keep the 3D world loaded across the warp see one seamless walk.
